# Comic Reader

An Ionic/Angular animated comic book reader with hard-cover page flips, soft comic pages, glowing magic background effects, and export tools for PDF/GIF sharing.

The real app lives in this `comic/` folder. The `../start_viewer.command` file belongs to an older viewer and is not used by this app.

## Tech Stack

- Angular 20
- Ionic 8
- PageFlip (`page-flip`) for the interactive book animation
- Node scripts for page normalization and exports

## Project Structure

```text
src/app/home/home.page.ts      Reader data model and PageFlip setup
src/app/home/home.page.html    Reader template, book pages, export menu
src/app/home/home.page.scss    Book styling, underlays, magic background
src/assets/comics/bookends/    Cover, inside cover, back cover, blank page
src/assets/comics/chapter*/    Normalized comic pages
scripts/normalize-pages.mjs    Normalize chapter pages
scripts/export-pdf.mjs         Generate static flipbook PDF
scripts/export-gif.mjs         Generate animated GIF export
www/                           Generated build output, do not edit manually
```

## Normalize Comic Pages

Put new images into a chapter folder, then rename them as `page_1.png`, `page_2.png`, etc. Run:

```bash
npm run normalize:pages
```

This normalizes every `src/assets/comics/chapter*` folder to `1024x1536`, adds the old-paper border texture, and stores local backups in `_original_sizes/`.

The `_original_sizes/` folders are intentionally ignored by Git because they can become large and are not needed for the deployed website.

## Exports

Generate the static PDF:

```bash
npm run export:pdf
```

Generate the animated GIF:

```bash
npm run export:gif
```

Warning: the GIF can be very large because it contains page-flip animation frames. The current export is roughly 90 MB, so it is not generated during the normal GitHub Pages build.

The reader menu always contains the PDF export. The GIF export appears only when `assets/exports/comic.gif` exists. The normal GitHub Pages build includes the PDF only. To include the large GIF in a local `www/` build, use `npm run build:full`.

## Build

Normal local production build:

```bash
npm run build
```

GitHub Pages build with the correct base href:

```bash
npm run build:pages
```

Full local build including the large animated GIF:

```bash
npm run build:full
```

Normal builds intentionally ignore `src/assets/exports/*.gif` so an old 90 MB GIF does not get copied accidentally. `build:full` copies it into `www/assets/exports/` after Angular finishes.

## GitHub Pages

This repo includes a GitHub Actions workflow at:

```text
.github/workflows/deploy-pages.yml
```

The workflow:

- uses Node 20
- runs `npm ci`
- runs `npm run build:pages`
- copies `www/index.html` to `www/404.html` for SPA fallback
- uploads `www/` to GitHub Pages

For a project site named `Comic`, the app is built with:

```bash
ng build --base-href /Comic/
```

The deployed URL should be:

```text
https://apollonius22.github.io/Comic/
```

## Notes

- Edit files in `src/`, `scripts/`, and `src/assets/`.
- Do not edit `www/` manually. It is regenerated by builds.
- Generated exports in `src/assets/exports/` are ignored by Git.
- The app adds a blank page only when the total content page count is odd, so the final spread does not get an unwanted empty page.
